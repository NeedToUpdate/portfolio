Every post on icandoathing.com starts with "I". I made a CPU. I automated my apartment. I found the impostors. That was the idea: one place to show a thing you made, and how you made it.

I built it to learn Vue and Django. I had used Vue once, for [my apartment control panel](/legacy/automated-apartment), and I had never shipped a Django app. I wanted a project big enough to raise real problems: accounts, uploads, feeds, search, moderation, deployment. A social site has all of them.

The first commit landed on December 15, 2021. By the end of April 2022 the repository had 315 commits and the site was live. No AI code-assist tools existed yet. The best we had was IntelliSense. I worked from the documentation, a Figma file, and a TODO list.

## What the site does

A post is a project, and a project has a state: planning, in progress, stalled, or completed. The home page shows every post as a gallery or a list. Visitors sort by popular, most liked, most viewed, or latest, and filter by status.

Posts are built from sections. A section is one image, video, or YouTube link, plus a block of Markdown. The page lays them out as a walkthrough: picture, explanation, next picture.

Projects keep going after the first write-up, so posts take updates. An update adds new sections and moves the post back to the top of the latest feed. The apartment post has five.

Profiles carry a bio, social links, like and follower counts, and a showcase of the author's favourite projects. Tags, search, likes, and follows tie the rest together.

## How it is built

The frontend is a Vue single-page app. It started on Vue 2 and moved to Vue 3 along the way, with Vue Router, Vuex, and axios. The styling is hand-written SCSS. There is no component library. I built the buttons, modals, notifications, and upload control myself.

The backend is Django with Django REST Framework on PostgreSQL. It handles token authentication, email activation, invite codes, and bans by user and by IP address. Uploaded images go to object storage, where the server converts them to WebP and makes thumbnails.

Post IDs are six characters, so URLs stay short: `/thing/pG7w9I`. The slug after the ID is the first 40 characters of the title. That is why some of the old URLs stop mid-word.

## Where it ran

The site moved often. It started on Heroku. The frontend then moved to Vercel, and the backend went into Docker on a DigitalOcean droplet. The backend now lives on a Webdock VPS, with the media on S3.

## What I would change

The code works, and it reads like someone learning. Most endpoints validate request fields one at a time where a serializer would do the work. The feed runs far more queries than it needs. There are no tests. Deploys ran from a copy script. Today the same site would ship from a pipeline, the way [this portfolio does](/insights/how-this-site-works).

## What it gave me

I finished with working knowledge of both frameworks. Weeks later I started [whatstheword.io](/legacy/whatstheword) on a Django backend.

The site also became my project log. I wrote eleven posts there between 2022 and 2024. They now live here, lightly cleaned up, in [the legacy archive](/legacy).
