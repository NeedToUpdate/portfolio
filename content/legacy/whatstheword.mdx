Kids love video games. Back in 2019, to make my classes fun (and easier for me), I decided to use my programming skills to make some games for the kids to play.

The first game I made was this one here. You had to drag and drop the letters while flying obstacles and monsters attacked you.

</MediaRow>

<MediaRow
  src="/images/legacy/whatstheword/02.webp"
  alt="A side-scrolling fighting game with a superhero facing a horned boar creature in a lava cave"
  side="right"
>

Another game was a simple sidescroller fighting game. I could add any transparent PNG to the game and have the kids' favourite characters: Ironman, Superman, random princesses, etc.

This game turned out to be the kids' favourite.

</MediaRow>

<MediaRow
  src="/images/legacy/whatstheword/03.webp"
  alt="The first game menu: a grid of twelve game tiles around a box for typing in the words for the class"
  side="left"
>

I made 12 games at first, and this was the main page of the games. They were all essentially just static HTML pages on my USB. I would open up the index file on the school touchscreen computer, and type any words I needed to teach that class. The kids would then choose a game, and we could play it. My classes became by far the most fun. Kids would come to class just to play the games.

</MediaRow>

<MediaRow
  src="/images/legacy/whatstheword/04.webp"
  alt="A later version of the menu with more than twenty game tiles"
  side="right"
>

Over time I made even more games. Each one is unique and fun, and all are customizable and flexible. All are written in vanilla JavaScript, completely from scratch.

</MediaRow>

<MediaRow
  src="/images/legacy/whatstheword/05.webp"
  alt="The whatstheword.io landing page, headed 'Class Getting Stale? We Have You Covered.'"
  side="left"
  wrap
>

Selling the games in that form was near impossible. I had Python files that would scan the folder for images, and create static JS files with all the config information, so the static HTML files could load the right images. Basically impossible to make user-friendly.

So I brushed up on my design skills, and created whatstheword.io.

With a Django backend and a React frontend, I can now sell the games as a SaaS (payments handled by Stripe), and make them very user-friendly.

</MediaRow>

<MediaRow
  src="/images/legacy/whatstheword/06.webp"
  alt="The wordlist manager, with rows of saved wordlists and buttons to use, edit, delete or publish each one"
  side="right"
>

Users can upload their own wordlists, share them online, and download others' lists.

</MediaRow>

<MediaRow
  src="/images/legacy/whatstheword/07.webp"
  alt="The image manager, with panels of uploaded characters, monsters, backgrounds and projectiles"
  side="left"
>

No need for Python scripts to scan for images. Just drag and drop your image, and it will appear in your games!

</MediaRow>

<MediaRow
  src="/images/legacy/whatstheword/08.webp"
  alt="The whatstheword.io game library, a grid of games with new licensed artwork"
  side="right"
>

And now all the games have graphics that I have a license to use. The classroom versions leaned on fair use for education, which stops applying once I sell them.

The whole thing took me around 2-3 months, working in my free time when I'm off work.

But it's now done!

</MediaRow>

## Update

whatstheword.io is offline now. It was fun while it lasted, and I still had a few users (all old coworkers). Unfortunately, AWS free tier changes made the site a bit too pricey to host.

I've also since learned a ton about better deployment and infrastructure strategies. I plan to rebuild it in a much more efficient manner, so it fits in a free tier again.
